# Changelog

## 0.2.0 (unreleased)

### Added

- The sandbox plugin client: `sandbox()` on an instance handle runs commands,
  follows their output, feeds standard input and moves files, and `plugin(name)`
  on one addresses any other plugin. The plumbing is `ukc.api.plugins.sandbox`.
- `ukc.images`: what each metro's nodes cache, and `find`/`exists` against the
  registry itself through the control plane.
- `ukc.templates`: `prepare` a template from an instance specification, `clone`
  instances out of it, and list, read and delete them, by tag too.
- Instances: `Instance.stop` decodes why an instance stopped, `create` raises
  `InstanceStoppedError` when the instance it made stopped instead of running,
  `delete` waits, forgives a missing instance and retries a busy one, and
  `each(tags=...)` addresses every instance that carries the given tags.
- A `create` whose wait lapsed raises `WaitTimeoutError` with the instance it
  made on `err.errors`; a wait of `-1` on `wait`, `delete` or `create` leaves
  the read timeout unbounded; `Instances.delete` takes `timeout_seconds` too;
  and `ResponseError.state` says what state a failed item was in.
- The transport is public: `request`, `request_no_content`, `request_bytes`,
  `stream_bytes` and `stream` on `ApiClient`, and `RawResponse` for payloads
  that are bytes.
- The platform and control-plane plumbing regenerated from the current
  specification: the audit event stream, the `services` module, and request
  models whose required fields are required.

### Changed

- `unikraft-cloud-plugin-sandbox-api` is a dependency: the sandbox plumbing is
  generated by plugin-sdk and packaged on its own.
- A request model's required fields are required at construction, so a request
  missing one raises pydantic's `ValidationError` before anything is sent.
- The plumbing's `ServiceGroupsApi` is `ServicesApi`, after the specification's
  tag, and the `body` of `get_instance_logs` and `wait_instances` is required.
- The private transport methods (`_request`, `_stream`, ...) are gone; the
  public names above replace them.
- `or_absent` resolves to `None` only for a resource reported missing
  (`NotFoundError.absent`); a 404 from a route that is not there is raised.

### Removed

- `UsersApi.add_users` and its models, which the specification no longer has.

### Fixed

- A handle or set whose lookup failed looks the resource up again on the next
  await, instead of raising the first failure again; an operation chained onto
  it does the same, while its own outcome still stands.
